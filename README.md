# WONJUN Journal

사진과 짧은 기록을 중심으로 만든 Astro 정적 블로그입니다. GitHub Pages에 배포되며, 콘텐츠는 MDX 파일로 관리합니다.

## Local development

```bash
npm install
npm run dev
npm run check
npm run build
```

`npm run build`는 Astro 정적 빌드 뒤 Pagefind 검색 인덱스까지 생성합니다.

## Write a post

`src/content/posts/YYYY-MM-DD-slug.mdx`를 만들고 아래처럼 작성합니다.

```mdx
---
title: Morning notes
description: A short description for cards and search.
date: 2026-09-25
category: LIFE # DEV | ENGLISH | BJJ | DIVE | DISTILL | LIFE
postType: journal # moment | journal | gallery | feature
cover: /images/journal/morning.jpg
coverAlt: A clear description of the image
tags: [notes]
featured: false
draft: false
---

본문을 여기에 작성합니다.
```

`postType`은 Astro MDX의 예약 필드인 `layout`과 충돌하지 않도록 분리한 콘텐츠 유형 필드입니다. `public/images/` 아래에 이미지를 저장하고 `/images/...` 경로로 참조합니다. 커버와 본문 이미지에는 의미 있는 `alt`를 작성합니다.

## Visitor statistics

블로그의 `누적 방문`은 GoatCounter의 **페이지별 방문 합계**이며 사이트 전체의 순사용자 수가 아닙니다. 같은 세션에서 같은 페이지를 새로고침하면 일반적으로 중복 집계하지 않지만 다른 페이지 방문은 추가됩니다. 순사용자 분석은 별도로 연결된 Google Analytics의 사용자 지표를 확인합니다.

`오늘(UTC)`는 UTC 00:00부터 현재까지입니다(한국 시간 오전 9시 초기화). 공개 카운터 API는 날짜를 UTC 자정으로 해석하므로 `start=YYYY-MM-DD`만 보내고 `end`는 생략합니다. 같은 날짜의 `end`를 보내면 하루 전체가 아닌 첫 시간만 조회합니다. 이 API는 한국 시간 자정 경계의 조회를 지원하지 않습니다.

공개 카운터의 공식 안내는 최대 4시간 캐시이지만, 2026-10-18 QA에서 응답 `Age`가 약 6시간 30분인 경우를 관측했습니다. 따라서 실시간·4시간 이내 반영을 보장하지 않으며 화면에는 수시간 이상 지연될 수 있다고 안내합니다. 브라우저는 누적·오늘·글별 수치를 직접 조회하며, 실패하면 같은 출처의 `public/data/goatcounter.json` 저장값을 사용합니다. 숫자의 툴팁은 저장값의 **조회 시점**이며 원본 데이터가 처리된 시점은 아닙니다. 이전 UTC 날짜의 오늘 값은 재사용하지 않으며 요청 실패를 0으로 표시하지 않습니다.

페이지를 열어 둔 동안 같은 기간에서 이미 확인한 수치보다 작은 캐시 응답은 무시합니다. UTC 날짜 변경 시 오늘 값만 초기화합니다. 오늘·글별 방문이 누적보다 크면 갱신 시점 불일치로 보고 해당 값을 `—`로 표시하며, 누적이 따라오면 다시 표시합니다. 배포 저장값에도 모순된 부분 집계는 넣지 않습니다. 합계를 임의로 늘리거나 방문 이벤트를 만들어 숫자를 맞추지 않습니다. 관리자가 원본 기록을 삭제한 경우 원본 캐시와 배포 저장값이 갱신된 뒤 페이지를 새로 열면 감소가 반영됩니다. 화면에도 `지연 집계`를 표시해 실시간 값으로 오해하지 않도록 합니다.

배포 워크플로는 15분 간격으로 예약되어 있으나 GitHub 예약 실행은 지연될 수 있으며, GoatCounter 자체 캐시를 우회하지 않습니다. 갱신 스크립트는 JSON API를 최대 4개씩 요청하고 실패한 항목은 최근 배포의 유효한 값과 원래 조회 시점을 보존합니다. 새 글의 실제 0건 응답은 0으로 저장합니다.

로컬·자동화·iframe·`skipgc=t` 브라우저는 수집에서 제외합니다. 숨겨진 탭은 처음 보여질 때 한 번 수집하며 탭 복귀나 BFCache 복원은 다시 수집하지 않습니다. 카테고리 구분은 유지하고 배포 확인용·추적용 쿼리로 같은 페이지의 통계가 나뉘지 않도록 합니다. 회귀 검증은 `npm run test:stats`로 실행합니다.

참고: [공개 카운터](https://www.goatcounter.com/help/visitor-counter), [방문과 세션](https://www.goatcounter.com/help/sessions), [날짜 처리 구현](https://github.com/arp242/goatcounter/blob/main/handlers/vcounter.go).

## Veracruz edge widget

필터 없는 홈에서만 흰색 베라크루즈 일러스트가 화면 테두리를 주행합니다. 헤더와 푸터는 물리 공간 밖에 두고 본문은 가운데에서 스크롤합니다. 홈 푸터는 60px 단일 도구 바로 정리하며 모바일의 저작권·방문 통계는 메뉴 안에 유지합니다. 링크와 부스트의 터치 높이는 최소 44px입니다. 모바일은 작은 차체와 완만한 사각 경로를 사용하고 차량 버튼의 실제 터치 높이는 최소 44px로 유지합니다. 390×844 기준 홈 푸터를 104px에서 60px로 줄여 본문 높이 44px와 도로 한 바퀴 길이 88px를 추가 확보했습니다. 현재 한 바퀴는 약 1744px이고 위아래 직선 구간은 각각 약 131px입니다.

| 입력 | 동작 |
| --- | --- |
| 차량 클릭/탭 | 기본 → 낮게 → 높게 차고 전환 |
| 차량 또는 부스트 더블탭 | 킥플립 |
| 공중으로 끌어 놓기 | 흡착 해제 → 중력 낙하 → 공중 추진 보정 → 바닥 접지 |
| 부스트를 누르고 놓기 | 200ms 미만 일반 부스트, 풀차지에서만 다음 코너의 램프 점프 |
| 부스트 위로 쓸기 / 아래 방향키 | 노말·스포츠·오프로드·머드 선택 |
| 차량에 초점 후 K / B | 킥플립 / 일반 부스트 |
| 부스트에 초점 후 Space / Enter | 누른 시간만큼 충전 후 놓아서 발사 |
| Escape | 설정 닫기 또는 충전 취소 |

환경 패널이나 메뉴를 열어도 주행합니다. 정차·에어 홉·앞쪽 낮추기 버튼은 없습니다. 동작 줄이기 설정에서는 이동·회전·급가속을 생략하며 차고와 환경 조작은 유지합니다.

공중의 중력은 모든 모드와 스킬에서 9.81m/s²입니다. 질량은 이전 기준의 2배이며 중력을 바꾸지 않고 필요한 보정력을 늘립니다. 벽 주행은 흡착 제약으로 유지합니다. 공중에서는 발사·회전·벽 회피·착지 제어가 실제 가속도에 필요한 힘을 계산하고, 그 힘과 토크에 비례해 공기를 분출합니다. 무게 중심과 앞뒤 하중은 연출을 위한 근사치이며 실차 측정값이 아닙니다.

킥플립의 공기 분출 순서는 다음과 같습니다.

1. 0–0.14초: 출발 벽 방향으로 밀어내는 도약 분사와 대각 회전 시동.
2. 회전 전반: 가까운 쪽 하부와 반대쪽 루프의 앞뒤 노즐이 회전 가속. 각 대각 쌍은 같은 크기의 반대 힘으로 순양력을 추가하지 않습니다.
3. 중간: 회전 관성을 유지하는 짧은 저토크 구간. 90°/270°에서 양력이나 벽 회피가 필요하면 측면 트림 노즐이 분사하고, 깊이 방향의 회전 분사는 짧게 퍼지는 분무로 보입니다.
4. 회전 후반: 대각 쌍을 뒤집어 역분사하고 회전을 제동합니다. 같은 물리 노즐의 명령은 합성해 한 방향으로만 분사합니다.
5. 하강: 전후 하중·자세·속도·벽까지의 정지 거리에 따라 공중에서 비대칭 보정. 보정력에 따라 짧은 제트와 얇은 잔연이 생기며 차체와 노즐 방향을 읽을 수 있도록 시각 압력만 완만하게 제한합니다.
6. 접지: 순양력을 끊고 짧게 중력으로 떨어진 뒤 에어서스는 접지 충격을 약 0.22–0.30초의 매끄러운 하중 펄스로 나눠 받습니다. 차체는 약 0.3–0.5초에 완만하게 눌린 뒤 작은 반동을 거쳐 원래 차고로 돌아갑니다. 단단한 이동 한계에 부딪혀 속도가 갑자기 끊기지 않도록 차고별 여유를 둡니다. 연무는 접지 후 빠르게 걷혀 서스펜션 움직임을 볼 수 있습니다.

램프는 출발 자세를 이어 받아 필요한 360° 방향으로 정렬하고 같은 공중 보정·접지를 사용합니다. 드래그는 실제 차량의 표시 위치를 샘플링하고 물리 경계 밖 방향의 놓는 속도를 제거합니다. 바닥 가까이에서는 점진적으로 수평을 맞추고, 지면 아래로 당겨 놓아도 추가 도약 에너지나 예전 비행의 회전·착지 명령을 전달하지 않습니다. 의도적인 위쪽 던지기와 드래그 취소는 남은 관성으로 낙하하며, 접근하는 네 벽 각각에 맞는 분사를 사용합니다. 희미한 미세 보정은 힘에 따라 연속적으로 사라져 닫힌 밸브처럼 보이는 노즐에서 큰 흰 불빛이 남지 않게 합니다.

차체는 원래 측면 에셋과 닫힌 캔버스 메쉬를 사용하고 노즐·바퀴·에어스프링은 같은 투영계를 공유합니다. 공중에서는 바퀴가 최대 길이로 늘어지며 차체와 바퀴의 질량 중심을 보존합니다. 배기는 화면 밖 128px까지 여유를 둔 별도 캔버스에 그리며 입자 수는 모바일 168개/데스크톱 240개, 비트맵은 최대 4M픽셀로 제한합니다. 노즐 압력은 75ms 응답으로 서로 교차 페이드하고, 깊이 방향 분무는 각도에 따라 연속적으로 변화합니다. v15보다 입자 발생률을 50% 늘리고 분무 크기·농도를 높여 분사 방향이 잘 보이게 합니다. 이전의 자욱한 연무보다 작고 짧게 유지하며 레이어 불투명도는 0.66으로 제한합니다. 착지 중 옅어진 입자는 다시 잡아도 이전 밝기로 되돌아가지 않습니다. 물리 엔진의 힘과 주행 경로는 그대로 유지합니다.

현재 모듈은 car-dynamics, car-route, car-ride, car-thrusters, car-projection, car-mesh, car-exhaust입니다. car-motion과 car-physics의 기존 API는 캐시된 이전 클라이언트를 위해 유지합니다. 현재 모듈과 엔트리의 캐시 버전은 20261017-16입니다.

검증: npm run test:car의 52개 검사에 2,880회 킥플립, 20,480개 코너 프레임, 17,568개 혼합 분사 자세, 네 모드×8구간×3스킬의 96개 비행이 포함됩니다. scripts의 로컬 전용 QA 페이지로 실제 입력, 앞뒤/상하/측면 분사 정렬, 73개 회전 프레임, 착지 시퀀스, 320×568부터 1920×1080까지 8개 화면 크기의 홈 메뉴 간섭을 검수합니다. 바닥 아래 놓기 1440개 순수 물리 경우와 car-floor-qa.html의 실제 홈 드래그 회귀 검사를 함께 수행합니다. public에 복사한 QA HTML은 배포 전에 반드시 제거합니다. car-exhaust-qa.html은 네 모드의 킥플립, 착지 후 다시 잡기, 일반 부스트, 풀차지 램프에서 차량 주변 프레임의 연기 밝기를 샘플링해 번쩍임과 잔광을 검사합니다. 실제 iOS Safari/Android 기기 검증은 이 Chromium 뷰포트 검증에 포함되지 않습니다.

## Structure

- `src/content/posts/`: 게시물과 frontmatter
- `src/content.config.ts`: 콘텐츠 스키마와 카테고리 유효성 검사
- `src/layouts/`: 공통 프레임과 글 레이아웃
- `src/components/`: 카드와 앞으로 확장할 MDX 구성 요소
- `public/images/`: 로컬 이미지
- `.github/workflows/deploy.yml`: GitHub Pages 배포

## Deployment and expansion

`master` 또는 `main`에 push하면 Actions가 검사, 빌드, Pagefind 인덱싱, Pages 배포를 실행합니다. GitHub Pages의 Source를 **GitHub Actions**로 설정해야 합니다. 커스텀 도메인은 `public/CNAME` 파일을 추가해 연결합니다.

현재는 로컬 이미지를 사용합니다. 이미지가 많아지면 frontmatter의 URL만 Cloudinary 또는 R2 URL로 교체하는 방식으로 외부 스토리지로 옮길 수 있습니다. 편집 UI가 필요해지면 Decap CMS나 Git 기반 CMS를 추가해 같은 MDX 구조를 그대로 유지할 수 있습니다.
