# 주짓수 위젯 원점 재검토

검토일: 2026-11-04. 기존 구현·일정·에셋·파일 형식을 유지한다는 전제를 해제한 설계 판단이다. 새 애니메이션 구현이나 시각 검수 완료 보고가 아니다.

## 결론

현재 절차적 캐릭터와 좌표 기반 동작 생성기를 최종 제작 경로에서 교체한다. 브라우저는 완성한 두 사람의 동작을 재생하는 역할에 집중한다. 삼각조르기 한 편을 먼저 새 경로로 제작·검증한 뒤 더블렉, 마운트 암바, 오모플라타, 보우앤애로우에 적용한다. 다섯 기술의 개선 목표는 유지한다.

360도 보기, 균일한 인체 비례, 기술의 정확성, 자연스러운 접촉은 제품 목표다. 제거할 대상은 이 목표가 아니라 기존 방식에 맞추려던 구현상의 전제다.

## 직접 확인한 근거

- `bjj-widget.ts`의 `Grappler`는 한 몸통 그룹에 골반·목·머리를 붙인다. 척추 분절, 독립적인 견갑대, 목 관절이 없다. 팔다리는 별도 원통을 양 끝점에 맞춰 놓는다. 몸통을 굽혀 상대를 감싸는 동작 자체를 표현하기 어렵다.
- `bjj-poses.ts`의 삼각은 여섯 개의 수작업 자세를 사용한다. 많은 저장 프레임은 이 적은 자세에서 계산한 결과이며, 관측한 연속 동작의 양을 뜻하지 않는다.
- `repair-bjj-motion.py`는 팔다리 끝점·굽힘 방향과 골반 이동을 최적화한다. 몸통 관절을 새로 만들거나 실제 하중 전달을 추정하지 않는다. 잔차의 충돌 항은 900, 원래 끝점 보존은 1.5 또는 3을 곱한다. 항의 단위·개수가 달라 이 수치만으로 실제 영향 비율을 계산할 수는 없지만, 충돌 감소와 원래 자세 보존이 서로 경쟁하는 구조임은 분명하다.
- 삼각의 마지막 잠금 검사는 발목과 반대 무릎의 거리 등을 확인한다. 그 거리만으로 상대의 목과 한쪽 팔이 올바르게 포획되었는지, 접촉 방향이 맞는지 증명하지 못한다.
- 기존 네 방향 삼각 렌더(`research/collision-triangle-transitions/triangle.png`, 저장소 밖)를 다시 검토했다. 떠 있는 듯한 지지 자세와 굳은 상체가 보이고, 가려지는 방향에서는 다리 잠금 구조를 읽기 어렵다. 정지 이미지 검토이며 연속 재생의 자연스러움을 판정한 것은 아니다.
- 기존 54개 숏츠 조사는 각 영상의 열 장 시간 샘플 검토였다. 유용한 비교 자료이지만, 연속적인 3D 동작 데이터나 모션 캡처가 아니다.

## 제작 경로 비교

| 경로 | 가치 | 한계 | 판단 |
| --- | --- | --- | --- |
| 두 사람 동시 다중 시점 캡처 + 수작업 정리 | 같은 공간에서 두 사람의 연속 움직임을 확보할 수 있다. | 촬영·동기화·리깅·가림 구간의 정리가 필요하다. | 사용할 수 있다면 우선한다. |
| 적합한 기존 두 사람 모션 + 수작업 정리 | 촬영을 줄이고 원래의 타이밍을 활용한다. | 정확한 기술·변형·사용 권리·품질을 개별 확인해야 한다. | 확보 여부를 확인한 뒤 채택한다. |
| 연속 시연을 기준으로 두 사람을 함께 키프레임 제작 | 특정 기술과 접촉을 직접 통제할 수 있다. | 애니메이터의 제작과 반복 검수가 필요하다. | 적합한 캡처가 없으면 현실적인 기본 경로다. |
| 단안 영상 자동 추정·텍스트 모션 생성 | 초벌 타이밍·자세 후보를 얻을 수 있다. | 밀착·가림·사람 식별·깊이·그립 오류를 남길 수 있다. | 초벌 보조로만 사용한다. |
| 현재 IK에 충돌 항을 더 추가 | 기존 코드를 바로 수정할 수 있다. | 표현력이 부족한 리그와 동작 근거 문제를 해결하지 못한다. | 최종 제작 경로로 채택하지 않는다. |

이 세션에서 새로 사용할 삼각조르기 모션 캡처나 완성된 리깅 에셋을 확보한 것은 아니다. 공개 데이터셋 검색 결과가 있다는 이유만으로 해당 기술의 상용 배포 가능 에셋이 준비됐다고 간주하지 않는다. 전면 물리 시뮬레이션 또한 기술의 정확성을 자동으로 제공하지 않는다.

## 새 제작 구조

1. **기준 시연 선정:** 기술당 기존 열 개 이상 비교 자료를 활용하되, 한 가지 진입과 마무리를 일관되게 보여주는 연속 시연을 제작 기준으로 고른다. 서로 다른 변형의 부분 자세를 섞지 않는다. 영상의 타임코드와 관측 가능·가림 구간을 구분한다.
2. **공통 리그:** 실제 단위와 하나의 바닥 좌표계를 사용한다. 골반, 다분절 척추, 흉곽, 쇄골, 목·머리, 고관절, 무릎, 발목, 발가락, 팔꿈치, 전완 회전, 손목·그립을 제어할 수 있는 골격과 스킨 메시를 쓴다. 두 사람의 비례는 기준 포즈에서 먼저 확정한다.
3. **한 장면에서 동시 제작:** 두 사람을 같은 시간축과 공간에서 작업한다. 각자의 애니메이션을 따로 만든 뒤 가까이 놓는 방식을 피한다. 그립과 지지 접촉은 상대 신체의 로컬 표면에 연결한다.
4. **접촉 구간 기록:** 접촉의 시작·유지·해제를 명시한다. 바닥 지지, 손목 제어, 다리와 목·어깨의 접촉, 발목과 무릎 뒤의 잠금은 서로 다른 관계다. 모든 접촉을 끝점 간 거리 하나로 대체하지 않는다.
5. **국소 보정:** 연속 동작을 유지하며 관절 제한, 발 미끄러짐, 충돌을 수정한다. 수정 때문에 기술이 무너지면 원래 애니메이션 단계로 돌아간다. 충돌 오차를 없애려고 전체 자세를 계속 밀어내지 않는다.
6. **배포:** 검수한 골격 애니메이션을 GLB 등으로 내보내고 브라우저에서 재생한다. 필요한 경우 접촉을 위한 작은 런타임 보정만 적용한다. 새 형식과 로더는 실제 에셋을 기준으로 선택한다.

## 삼각조르기 우선 검수

정확한 좌우 방향과 각 단계의 자세는 선정한 기준 시연에 맞춰 확정한다. 아래는 동작을 만들어내는 좌표가 아니라 검수 질문이다.

- 진입부터 마무리까지 동일한 두 사람과 좌우 다리가 추적되는가?
- 한쪽 팔이 안에, 다른 쪽이 밖에 있는 관계가 각 시점에서 유지되는가?
- 다리를 넘길 때 상대의 머리·어깨를 실제로 돌아가는가? 한 프레임의 잠금 자세만 맞춘 것은 아닌가?
- 골반 회전·상체 굽힘·상대 자세 변화가 연속적으로 연결되는가?
- 잠금은 발목과 반대 무릎 뒤의 표면 관계로 읽히는가? 목과 포획된 어깨를 포함한 구조도 맞는가?
- 지지하는 발·무릎·등·골반은 그 구간에서 매트 또는 상대와 접촉하는가? 지지점이 움직이면 몸도 그에 맞게 반응하는가?
- 손이 잡고 있는 신체 부위가 유지되며, 손을 놓을 때 전환이 보이는가?

## 완료 기준과 진행 순서

첫 산출물은 삼각조르기의 **연속 비교 영상**이다. 실사와 새 애니메이션을 동기화해 나란히 보여주고, 정면·측면·후면·상단과 느린 재생을 검토한다. 정지 접촉표, 뼈대 표시, 관통·미끄러짐 진단을 함께 둔다. 실제 WebGL 화면에서 드래그 360도·타임라인 탐색·재생도 확인한다. 기존 SVG 정지 렌더만으로 이 검수를 대체하지 않는다.

기술 정확성·실사 대비 자세·전환·접촉·보이는 품질을 각각 판정한다. 기술 지도자가 검토하지 않았다면 전문가 검수 완료라고 쓰지 않는다. 자동 테스트 통과는 이러한 시각 판정의 대체 증거가 아니다.

삼각 한 편에서 이 제작 경로의 개선을 확인한 뒤 같은 공통 리그로 나머지 네 기술을 제작한다. 삼각이 기존보다 낫다는 증거 없이 다섯 편으로 확대하지 않는다. 이번 재검토에서는 공개 위젯과 동작 데이터를 변경하지 않았다.

## 외부 근거와 해석 범위

- [MultiPhys, CVPR 2024](https://arxiv.org/abs/2404.11987): 두 사람의 단안 추정 모션을 물리 시뮬레이터로 보정하고, 관통과 발 미끄러짐을 평가한다. 연속 모션 추정과 물리 보정을 분리하는 접근의 근거다. 이 논문이 삼각조르기의 자동 복원을 보장한다는 뜻은 아니다.
- [Three.js 공식 문서](https://threejs.org/docs/): Skeleton, SkinnedMesh, AnimationClip, AnimationMixer 등 골격·애니메이션 재생 구성을 제공한다. 브라우저 엔진을 먼저 교체할 필요가 없다는 설계 판단에 참고했다. 최종 에셋의 품질은 별도 제작·검수 대상이다.
