# 삼각조르기 재제작 1차 작업

2026-11-04. 상태: **새 리그와 검토용 동작 초안 구현. 공개 위젯 교체 기준 미달.**

## 2026-11-05 접촉 재제작 작업 중

### 로컬 위젯의 흰색 오른쪽 다리 수정

최종 반영: 오른쪽 다리 표면 2,113개 시점(96Hz), 양측 시연자 네 무릎·발목 8,452건 검사에서 기준 초과 0건. glTF 재생·되감기·체격·연속성 검사 5개 통과, 타입 검사와 프로덕션 빌드 통과. 잠금 오른쪽 무릎 굽힘은 최소 약 121.28°. 실제 GLTFLoader 표면과 제작 원본의 최대 오차는 약 0.013mm다. 최종 자세 렌더 3개는 `../outputs/bjj-rebuild/right-leg-final/`에 보존했다. 최종 브라우저 육안 검사는 컴퓨터 제어가 현재 URL을 확인하지 못해 중단되어 완료하지 못했다. 전체 그립·목 접촉과 다른 네 기술은 미완료다.

닫는 중 발이 급히 접히던 구간의 속도를 낮췄다. 원본 13.5–16초를 표시 시간 13.5–19초로 늘리고, 두 사람에게 같은 시간 변환을 적용한다. 전체 길이는 22초다. glTF 시간 키를 함께 바꿔 확인된 공간 경로를 유지한다. `bjj-retime-leg.py`, `bjj-build-refined.py`의 `BJJ_WITNESS_ONLY=1`, `bjj-retime-glb.mjs`를 사용한다. Blender 비정수 프레임 직접 내보내기는 자세 오차가 있어 사용하지 않았다. 시간 변환 후 새 표본에서 발견한 추가 관통은 원본 15.25초 키를 재보정하고 앞뒤 키와 함께 재검증한다.

현재 브라우저에 표시되던 GLB를 직접 읽어 두 사람의 원래 관절 애니메이션을 복원했다. 실험 중이던 다른 전신 궤적을 원본으로 사용하지 않았다. 흰색 시연자의 양쪽 허벅지·정강이 축 회전, 발의 실제 발바닥 좌표계, 오른발의 골반 지지와 마지막 잠금 경로를 수정한다. 검토된 산출물만 **로컬** `src/assets/bjj/triangle-study.glb`에 반영한다. 공개 사이트에는 아직 배포하지 않았다.

오른발을 일찍 떼면서 상대 몸통 안으로 보내던 경로를 골반 지지로 바꿨다. 실제 골반 표면에 발바닥을 맞추고 무릎의 굽힘 평면을 함께 정렬한다. 13.5–19초에는 실제 두 고관절의 좌우 방향을 기준으로 몸 바깥을 돌아 잠근다. 양쪽 다리의 회전 기준을 바로잡으며, 잠금 접점에 필요한 왼쪽 다리의 위치 보정은 닫는 구간에 적용한다. 상체·팔·파트너의 원래 관절 경로는 보존하고, 두 사람에게 같은 시간 변환을 적용한다.

표면 접점만 맞추면 오른쪽 무릎을 펼친 자세도 통과하는 결함을 발견했다. 최종 잠금 구간(표시 시간 19–22초)에는 오른쪽 무릎 굽힘 110° 이상, 목표 120°를 별도로 요구한다. [GrappleMap](https://github.com/Eelis/GrappleMap)의 공개 수작업 `lock` 포즈(리비전 `032c8f91809786b7b784852abd07cf3e10c0ea35`, 시퀀스 679, 마지막 아래 시연자 오른쪽 무릎 약 119.7°)를 형태 참고로 사용했다. 해당 데이터의 모션을 가져오거나 지도자 검수 완료로 간주하지 않는다.

사이트가 읽는 모션 원본은 `assets/bjj/triangle-widget-poses.npz`, 검증 범위와 해시는 `triangle-widget-state.json`에 별도로 보존한다. 이전의 전신 보정 실험인 `triangle-contact-poses.npz`와 구별한다. 전체 관통·그립 개선 완료를 의미하지 않는다. 아래 초기 후보 수치와 실패 기록은 제작 이력이다.

- 원본 GLB 복원: `bjj-extract-runtime.mjs`, `bjj-import-runtime.py`
- 골반 지지와 외측 경로: `bjj-build-right-path.py`
- 관절 길이를 유지하는 표면 보정: `bjj-refine-right-leg.py`
- 독립 검사: `bjj-audit-right-leg.py`, `bjj-audit-knees.py`, `bjj-verify-right-leg.mjs`
- 브라우저 모션과 Blender의 표면/관절 비교: `bjj-verify-export.mjs`

### 오른쪽 다리 회전 축 결함

사용자 지적 후 실제 스킨의 무릎 앞면과 굽힘 방향을 비교했다. 기존 보정 후보의 흰색 오른쪽 무릎은 9초와 14초에서 앞면 방향의 내적이 각각 -0.931, -0.993이었다. 관절 위치와 굽힘 각도가 유효해도 허벅지·정강이의 축 회전이 반대였으며, 기존 관통/그립 검사로는 검출하지 못했다.

`set_leg_bone`은 두 개씩 나뉜 허벅지·정강이 뼈를 같은 해부학적 굽힘 평면으로 정렬한다. 자유로운 발은 정강이의 좌우 축을 따르고, 골반에 짚는 발은 발의 방향과 무릎의 IK 방향을 함께 맞춘다. `bjj-repair-leg-roll.py`는 기존 위치 경로를 이 방식으로 재구성하는 **보정 시작 데이터**를 만든다.

`bjj-audit-knees.py`는 96Hz의 2,113개 시점에서 네 무릎의 굽힘, 실제 스킨 앞면, 발목 좌우 축을 검사한다. `.astro/bjj-leg-roll-v3-seed`는 이 검사에서 실패 0개였으며, 앞면 방향의 최소 내적은 0.380, 발목 축은 0.420이었다. 이것은 전체 접촉/그립 통과나 기술 완성 판정이 아니다. 다리 표면이 바뀌었으므로 접촉과 전환을 재보정 중이며 사이트 에셋은 아직 교체하지 않았다.

기존 초안에 보정을 추가한 후보도 24fps 전체 검사에서 실패했다. 보정 키만 통과한 것을 연속 동작의 통과로 취급하지 않는다. 현재 공개 GLB는 교체하지 않았다.

- Blender와 WebGL에 같은 정규화된 네 개의 스킨 가중치를 적용한다. 실제 GLTFLoader/AnimationMixer의 변형 결과를 Blender 표면 표본과 비교하는 `bjj-verify-export.mjs`를 추가했다.
- `bjj-refine-contact.py`는 실제 변형 표면, 손바닥의 고정된 표면 지점, 손가락 끝, 목 뒤의 정강이, 발목 잠금, 접지를 함께 보정한다. 뼈 길이와 메시 정점을 독립적으로 늘리지 않는다. 이 수치 검사는 지도자 검수나 기술 정확성 인증을 대신하지 않는다.
- `triangle-hip-roll.json`은 골반을 14cm 들어 올리는 동안 머리와 등 상부의 지지 높이를 유지하도록 맞춘 척추/골반 궤적이다. 지지점 피팅과 두 사람이 접촉한 상태의 최종 동작 검사는 별개다.
- 발목 좌표 대신 발바닥 표면을 상대의 가까운 골반에 맞춘다. 움직이는 무릎 방향으로 표면을 찾으면 반대편 골반으로 점프하던 오류를 수정했다. 그립을 놓기 전에 상대 팔이 먼저 움직이던 순서도 분리했다.
- 빠른 오프라인 FK 어댑터는 Blender와 별도로 동작한다. 각 제작 변경 후 `bjj-fast-author.py`로 다시 비교해야 하며, 내보내기는 항상 실제 Blender를 사용한다.
- 후반 9–22초의 313개 시점 검사에서 세 시점이 기준을 넘었다. 수정된 세 자세를 만든 뒤에도 주변 구간을 다시 검사해야 한다. 진입 구간은 무릎/정강이가 바깥팔을 넘는 궤적을 계속 재제작 중이다.

현재 통과 조건은 표면 관통 후보 2.5mm, 손바닥 오차 8mm, 손가락 끝 오차 12mm, 기술 접촉점 오차 8mm, 바닥 침투 2mm 이하이다. 표면 내부 판정과 자체 신체 영역의 보수적 충돌체에는 한계가 있다. 이 한계와 별개로 눈에 보이는 잘못된 경로를 수치 통과만으로 승인하지 않는다.

보정된 두 자세가 각각 통과해도 그 사이의 SLERP에서 팔이나 엄지가 통과하는 문제가 남았다. `bjj-contact-path.py`는 중간 자세의 실제 스킨·그립·기술 접촉·바닥 조건을 끝 자세와 함께 보정한다. 회전의 미분은 비가환 회전까지 포함하며, 수치 미분으로 검증했다. 프레임만 검사하던 내보내기 비교에도 프레임 간 시점을 추가했다.

작업 중 보정 데이터 스냅샷은 `assets/bjj/triangle-contact-poses.npz`에 보존한다. 상태와 해시는 `triangle-contact-state.json`에 기록한다. 현재 상태는 **work-in-progress**이다. 전체 검사 결과와 검토된 GLB를 함께 확정하기 전에는 재제작 완료로 표기하지 않는다. 공개 GLB는 교체하지 않았으며 다른 네 기술도 아직 이 파이프라인으로 재제작하지 않았다.

## 구현한 것

- MakeHuman CC0 인체 메시, 기존 스킨 가중치, 163개 뼈의 계층을 사용하는 두 사람을 Blender 장면에 만들었다. 원본 데이터의 출처·리비전·라이선스는 `assets/bjj/README.md`에 보존했다. MakeHuman 애플리케이션 소스 코드는 복사하지 않았다.
- 두 사람은 동일한 1.78m 메시와 단위를 사용한다. 척추 5분절, 목, 손가락, 손목, 발을 독립적으로 제어한다. 복장은 인체 표면의 훈련복 표현이며 도복·옷깃·천 시뮬레이션은 아니다.
- 같은 장면에서 22초짜리 연속 동작을 수작업으로 블로킹했다. 기존 `bjj-poses.ts`, `bjj-motion-data.ts`, 기존 충돌 최적화 결과는 입력으로 사용하지 않았다. 모션 캡처·영상의 자동 3D 복원·지도자 검수 완료 자료가 아니다.
- 편집 가능한 `.blend`와 스킨 애니메이션 GLB를 출력한다. GLB는 브라우저에서 AnimationMixer로 직접 재생하며 0초부터 22초까지 두 사람을 함께 탐색한다.
- `/bjj-study/`에 별도 검토 화면을 만들었다. 재생·0.25/0.5배속·단계 이동·시점 프리셋·360도 회전·확대·골격 표시와 원본 유튜브 시연 링크/선택적 플레이어를 제공한다. 정투영으로 원근 때문에 두 사람의 크기가 달라 보이는 효과를 줄였다.
- 원본과 모델은 독립 조작한다. 타임코드의 자동 동기화는 구현하지 않았고, 가려진 동작을 측정했다고 주장하지 않는다.

## 검증과 그 한계

- GLB를 실제 Three.js GLTFLoader로 읽어 두 개의 같은 크기 스킨 메시·163개 뼈·가중치·유한한 애니메이션 트랙·22초 길이를 확인했다.
- 종료 위치에서 되돌아온 뒤 같은 시간의 자세가 동일한지 검사했다. 60Hz로 탐색하며 뼈의 비정상적인 순간 이동도 검사했다. 이 네 검사는 파일과 재생 통합 검사이며 자연스러움과 기술 정확성의 증거가 아니다.
- Chrome에서 실제 WebGL 모델 표시, 재생 진행과 단계/시점 이동을 확인했다. Blender 정지 렌더와 Workbench 연속 검토 영상도 생성했다. 유튜브 임베드의 브라우저 도구 관측에는 지연이 있어, 원본 링크를 항상 제공한다.
- Astro 검사: 오류 0, 경고 0, 기존 힌트 27. 전체 사이트 빌드 성공. 기존 공개 동작은 수정하지 않았다.

## 아직 실패하는 부분

단순 충돌체 대신 **실제 스킨 변형 결과**를 BVH로 진단했다. 최근접 표면 법선만으로는 팔다리 사이의 오목한 빈 공간을 관통으로 오판해, 광선 교차 홀짝 판정으로 내부 후보를 좁혔다. 그래도 열린 표면·접선 방향·얇은 부분에서는 오판할 수 있다. 이 값은 진단이며 완전한 충돌 판정이나 연속 시간 무관통 보장이 아니다.

초안의 실제 표면 진단에서 8초 부근에는 목·어깨·정강이 접촉 오류가, 16–22초에는 포획된 팔·허벅지와 손·머리 주변의 겹침이 남았다. 수 cm 수준의 내부 후보도 있어 미세 오차로 취급할 수 없다. 손의 모양과 그립, 접지 간격, 다리를 넘기고 다시 접는 전환 경로도 추가 제작 대상이다.

이 초안은 **인체와 제작 파이프라인의 교체를 확인하는 산출물**이다. 삼각조르기 품질 개선 완료로 배포하거나 나머지 네 기술을 이 초안의 동작에 맞춰 양산하지 않는다. 다음 제작에서는 문제가 있는 접촉 구간의 자세와 경로를 수정하고 원본 시연과 다시 비교해야 한다.
